# Changelog

Notable changes to PRS Apps, newest first. Each entry is a date heading (`## YYYY-MM-DD`) followed by 1–2 line bullets. Routine/trivial changes live in git history, not here.

## 2026-07-20

- **IT Tracker — Stage 5 (rack audit workflow):** migration `09_rack_audits.sql` adds `rack_audits` + `rack_audit_items` (RLS on). Starting an audit from the rack detail page snapshots the currently-mounted devices as expected items; the auditor then walks the rack marking each **Present / Moved / Missing** (with a found-at-U for moved), logs **unexpected devices found**, records per-item **condition** + notes and overall notes, then **Completes** the audit (or Discards an in-progress one). Completed audits are read-only. The rack page gained an **Audits** section (last-completed date + history list with status, auditor, and discrepancy count) and a **Start/Resume Audit** button. Snapshots preserve device name/type/expected slot so history survives later asset edits/deletes. Shared audit helpers (`AUDIT_RESULTS`, `AUDIT_CONDITIONS`, `countDiscrepancies`) in `lib/tracker.js`. **Reconciliation:** findings drive the live data — an unexpected ("extra") device has a **Create asset** action that opens `AssetModal` prefilled (name + rack + found-at-U) and links the new asset back to the finding; a **moved** device has an **Apply move → U#** action that repositions the real asset (overlap-validated); a **missing** device has a **Remove from rack** action (detaches `rack_id`/`u_position`, confirm-guarded). `AssetModal` gained a `defaults` prop to seed a new asset. Note: `rack_audit_items.asset_id` is `bigint` (matches the legacy `assets.id`, not uuid). **Run `09` in the Supabase SQL Editor to apply.**
- **IT Tracker — rack visualization redesign (Lucidchart-style):** the rack detail grid now looks like a physical server rack — a metal enclosure with a title bar and two mounting rails dotted with holes, a left U-number gutter, and **per-type device faceplates** (new `RackDeviceFace` component): switch/router/firewall show port rows, servers show a vent grille, Storage/NAS shows drive bays with activity LEDs, UPS shows round outlets, Monitor is a blue screen, everything else a generic plate — each with a status LED and a name chip that appears on hover. Interactions unchanged (click a device to edit, hover to Unmount, click an empty slot to place). `ROW_PX` bumped to 30.
- **IT Tracker — rack-mountability is now an explicit flag (Stage 4 follow-up):** migration `08_asset_rack_mountable.sql` adds `assets.rack_mountable` (boolean, backfilled true for the previously type-rackable set + anything already in a rack). The asset form now has a **Rack-mountable device** checkbox that gates the Rack/Power block, so *any* type — including "Other" — can be racked; `type` still drives which detail fields show (computer specs vs. management URL). Picking a type suggests a default for the checkbox on new assets only. Added an **overlap/fit safeguard**: saving a rack-mountable asset with a rack + U position is rejected if it exceeds the rack or collides with another device there (shared `rackPlacementError()` in `lib/tracker.js`, used by both `AssetModal` and `PlaceDeviceModal`). **Run `08` in the Supabase SQL Editor to apply.**
- **IT Tracker — Stage 4 (racks + U-position visualization):** new Racks app section — list page (`/tracker/racks`, per-rack device count / U used / total power) and a rack detail page (`/tracker/racks/[id]`) with a **to-scale, clickable U grid** (highest U at top, U1 at bottom; a device spans `u_height` U's from its `u_position`). Click a mounted device to edit it (`AssetModal`) or **Unmount** (keep in rack, `u_position` null); click an empty slot to open **`PlaceDeviceModal`** (pick a rackable unmounted device + bottom U, validated for fit/overlap). Devices assigned to a rack with no `u_position` show in an **Off-rack (in room)** column. Total power is auto-summed from device `watts` (not stored). `AssetModal`'s Rack/Power block gained a **Rack** picker (`rack_id`; clearing it clears `u_position`); `AssetDetail` shows the rack name + "Off-rack". New `RackModal` (name, cascading Location→Room, size in U, notes). Registered **Racks** in the tracker nav. No migration — `racks` existed from `05`, `room_id` from `07`.
- **IT Tracker — Stage 3 (asset type + type-aware detail):** `AssetModal`/`AssetDetail` gained a **Type** field (`ASSET_TYPES`) that drives which detail fields show. Computer types (Laptop/Desktop/Server) show a **Computer Details** block (hostname, IP, OS, CPU, RAM, storage); non-computer types show an optional **Management URL**; rack-mountable types (Server/Switch/Router/Firewall/NAS/UPS) show a **Rack / Power** block (watts, U-height, rack position). Added a `rackable` flag + `isRackableType()` to `src/lib/tracker.js` (the memory's "type drives rack eligibility"). On save, detail fields not applicable to the chosen type are nulled so rows stay consistent; the assets list now shows the type next to each serial. No migration — all columns existed from `05`.
- **IT Tracker — Stage 2 (employee detail + grouped asset views):** new employee detail page (`/tracker/employees/[id]`) showing the employee's info (email, department, title, location/room, manager) + a table of all assets assigned to them; employees-list rows now navigate there, and editing moved onto the detail page (the list keeps only "+ Add Employee"). Assets list gained a **Group by** control (None / Employee / Location) rendering one table per group with the catch-all bucket (Unassigned / No location) last. `AssetModal`'s free-text Location input replaced with cascading **Location → Room** dropdowns writing `location_id`/`room_id` (mirrors the employee form; pre-FK free-text shown as a migrate hint); asset detail now shows the FK location/room. No migration — `assets.location_id`/`room_id` already existed from `05`/`07`.

## 2026-07-17

- **IT Tracker — location → room hierarchy (Stage 1 rework):** migration `07_location_rooms.sql` adds a `rooms` table (belongs to a location) and `room_id` on employees/assets/racks; retires the flat `locations.site`/`locations.room` text columns. Locations list row now opens a **location detail page** (`/tracker/locations/[id]`) that manages that branch's rooms (`RoomModal`, add/edit/delete with in-use warning). `LocationModal` simplified to name/address/notes. Employee form now has cascading **Location → Room** dropdowns (room list filtered to the chosen branch; changing branch clears the room).
- **IT Tracker — Stage 1 follow-ups:** employee name split into `first_name`/`last_name` (migration `06_employee_names.sql`, backfilled from `full_name`, which the app still writes as the combined value); employee form now has separate first/last fields. Brought the **Locations** UI forward from Stage 2: `/tracker/locations` page + `LocationModal`, registered in nav; the employee form gained a **Location / Branch** dropdown (`location_id`) for multi-branch companies, surfaced as a column on the employees list.
- **IT Tracker asset management — Stage 1 (employees + real assignment):** new `/tracker/employees` directory page (list, search, active/inactive filter, per-employee asset count) with `EmployeeModal` add/edit (name, email, department, title, manager, status, notes). Registered in the tracker nav. Assignment moved off the free-text `prompt()` to a real employee FK: checkout now uses `CheckoutModal` (active-employee picker) writing `assigned_employee_id`; `AssetModal`'s "Assigned To" is an employee dropdown (shows a legacy-value hint for pre-FK rows). `assigned_to` is kept as a cached display/search name synced to the chosen employee. Assets list/detail resolve the assignee via an `employees(full_name)` embed.
- **IT Tracker asset management — Stage 0 (foundation):** first committed tracker DDL `supabase/05_tracker_schema.sql` (idempotent, RLS-on). Adds `locations`, `employees`, `racks` tables; asset columns for `type`, rack/device fields (`rack_id`, `u_position`, `u_height`, `watts`, `hostname`, `ip_address`, `os`, `cpu`, `ram`, `storage`, `management_url`), and relational `assigned_employee_id` / `location_id`. New **Asset ID** system: `PRS-#####` global sequence, immutable, auto-assigned on insert, existing rows backfilled oldest-first; the ID doubles as the printed asset tag. Added `src/lib/tracker.js` (shared statuses/categories/types/colors/formatters/depreciation) and `src/app/tracker/layout.js` (single `hasAccess('tracker')` guard for all `/tracker/*` pages — previously only the dashboard guarded). Asset components refactored onto the shared lib. **Run `05` in the Supabase SQL Editor to apply.**
- **Dev onboarding:** added `.env.example` (env-var template, no secrets; `!.env.example` un-ignored) and a "Setting up on a new machine" section in `README.md` (prereqs → clone → `.env.local` → run).
- **Agent config:** committed `.claude/settings.json` — auto-approves routine tool use, keeps `git add/commit/push` behind an `ask` prompt, and denies destructive commands (recursive deletes, `git reset --hard`, force-push, etc.).

## 2026-07-16 — Help Desk launch (replaces Invoice Processor)

- **Help Desk app** (`helpdesk`): Freshservice-style dashboard, dense ticket queue (SLA state / status / priority / assignee, filters), two-pane ticket detail, and an agent-logs-on-behalf "New ticket" form. Registered in nav, home tiles, and admin access.
- **SLA:** priority-based `sla_policies` stamp first-response/resolution due times on insert and recalculate on priority change (DB triggers); queue/detail show derived state (overdue / due today / on time).
- **Knowledge Base:** browse + search, markdown article view with helpful votes, and agent CRUD. "Document this resolution" links a resolved ticket to a similar article (pg_trgm + full-text `search_kb`) or opens a prefilled new article; articles list their related tickets.
- **Categories:** editable Category dropdown on tickets (changes logged to Activity); shared category list including "Price update".
- **Attachments:** file upload to Supabase Storage on tickets, download via signed URLs.
- **Email via Microsoft Graph (no Power Automate):** inbound push webhooks turn emails to `it@` / `priceupdate@` into tickets (`priceupdate@` → `price_update` category), de-duplicated by message id; outbound replies and assignment notices sent as `it@`. Daily Vercel cron renews Graph subscriptions.
- **Invoice Processor:** slated for retirement via the `app_access`/registry soft-hide — see `docs/deprecation-checklist.md`.
- **Repo/portability:** added `AGENTS.md` project guide; moved SQL migrations into `supabase/` (numbered, idempotent) and planning/setup docs into `docs/`.
